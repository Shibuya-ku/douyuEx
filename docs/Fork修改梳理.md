## 当前版本的产品改动

下表中的“修复选色加载时机”和“整理选色定时器”是 fork 新功能上线后的内部迭代；共同祖先尚无自动选色模块。

| 改动 | 上游或 fork 早期版本的体验 | 当前 fork 的体验 | 用户价值 |
|---|---|---|---|
| 新增自动最高弹幕色 | 没有“进房后自动选择最高已解锁颜色”的独立偏好 | 扩展功能中增加开关，首次关闭；开启即尝试选色，下次进入房间恢复偏好 | 经常切换直播间时，减少重复展开色板、选择颜色的操作。 |
| 修复选色加载时机 | 初版新增功能可能在色板尚未渲染时读取不到选项 | 先点击打开色板，再等待颜色项出现后选色 | 让自动选色适应异步加载的页面。 |
| 取消每周项目支持弹窗 | WeeklyPanel 初始化后按周期显示介绍/求 Star 浮层 | 从初始化清单移除调用 | 减少进入房间时的非观看内容打断。 |
| 去掉更新图标红点 | 检测到不同版本时显示文字通知和图标红点 | 删除红点节点及相关逻辑，保留文字通知和更新入口 | 减少持续的视觉提醒。 |
| 取消进房自动检查更新 | 页面启动时请求版本信息并可能提示更新 | 删除启动调用，仅保留油猴菜单手动检查；工具条更新图标仍打开安装页 | 把检查版本改为用户主动发起。 |
| 整理选色定时器 | 定时器句柄放在 `window` 属性中 | 改成脚本中的变量；再次启动前清理已有定时器 | 降低与网页全局状态耦合，属于维护性改进，没有新增用户操作。 |

### 自动最高弹幕色的具体行为

- 入口：主工具条 → 扩展功能 → “自动最高弹幕色”。
- 首次默认关闭，保存在 `ExSave_AutoBarrageColor`，不是各房间独立的偏好。
- 开启时立即尝试；随后进入房间初始化时，读取设置并执行一次选择。
- 同时识别普通房间和比赛房间的色板组件。
- 每 500ms 重试，最多约 50 秒；先打开色板，再等待颜色项渲染。
- 选择 DOM 顺序中最后一个没有 `is-lock` 的颜色项，用它代表“最高已解锁颜色”；没有自行计算粉丝等级，也不解锁账号没有的颜色。
- 选中后结束，不持续监控后续升级获得的新颜色。

源码：`src/packages/ExpandTool/ExpandTool_AutoBarrageColor.js:3`（初始化）、`:20`（开关）、`:36`（恢复偏好）、`:47`（等待和选色）；挂载在 `ExpandTool.js:20`。

已有的 BarrageLoop“循环发送时变色”与此功能不同：前者随发送轮换颜色，后者在进房时自动选择一个已有权限的最高档颜色。

### 减少打扰的修改边界

停用 WeeklyPanel 的方式是移除 `main.js` 中的调用，其源码和 CSS 仍保留。更新模块也仍保留：手动检查、文字通知、安装页链接都没有删除。此次改动不等于关闭所有插件通知或所有后台请求。

手动版本检查仍读取原作者的版本服务器，安装和更新说明也仍指向原项目；没有新增 fork 专属更新源。版本判定仍沿用“版本字符串不同”判断，未改成严格的新旧版本排序。

- WebSocket、其他 require 工具、common、路由和所有源码 CSS。
- build.js、package.json、package-lock.json、README 和 .gitignore。

它们仍是当前产品的一部分，但不是这批 fork 提交新增的功能。完整功能现状见[产品模块梳理](./产品模块梳理.md)。

`dist` 中较大的删行主要来自 CSS 换行压平、压缩变量重命名，以及停用入口后清理未引用函数；不能据此推断发生了大规模样式删除或播放器重构。本次检查没有发现只出现在构建产物中的额外媒体功能修改。

## 本次静态阅读发现的后续关注点

1. 自动选色正在等待色板时，关闭开关只保存设置，没有取消当前定时器；仍可能发生一次选色。依据：`ExpandTool_AutoBarrageColor.js:20` 与 `:47`。
2. 手动检查更新仍连向原作者服务，不是当前 fork 的发布源；后续若独立维护，更新入口的产品归属需要重新定义。
3. 当前 lite 与 master 内容一致。若继续做精简版，需要基于本次完整功能清单明确保留和移除范围，而不能把分支名本身当成已经完成精简。
