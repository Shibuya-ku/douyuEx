# DouyuEx Lite 精简需求与开发方案

版本：v0.2（已确认并实施）
日期：2026-11-17
开发基线：`lite` / `86a7f72`（开始开发时与 `master` 相同）。
本轮交付：需求、实现与验收依据。用户已确认本方案，业务代码已按本文件实施；详见 [Lite 开发与测试报告](./Lite开发与测试报告.md)。

v0.2 修订：按用户“观看时长奖励还有 30 分钟时也能领取，禁止影响正常使用”的要求，撤销 v0.1 将等级/观时领奖改为手动一次执行的提议。保留原有自动检查、后续时段检查和到点触发；新增时序清单与跨时段验收。本文中 v0.2 的要求取代旧提议。

## 1. 产品目标

保留现有直播观看体验、fork 后的改进，以及指定的签到、续牌、钓鱼和在线弹幕助手入口；收拢工具条，移除无关业务、外部服务及遗留功能，消除简单布局切换时多余的确认弹窗。

Lite 的目标是“观看功能完整，工具入口精简”。不是通过隐藏图标保留全部后台功能，也不以文件数量或构建产物删行数量作为完成标准。

**不影响正常使用是硬性约束。** 保留一个功能时，必须一并保留它的自动触发、重复检查、到期执行、日期选择、失败重试、消息心跳/重连、页面异步等待、后续事件监听、必要刷新及结束清理。不能以减少请求或定时器为理由，将它降级成手动操作或只执行一次。只有整份方案最终确定移除的功能，才清理其专属后台行为；共用调度与数据依赖先拆分再保留。

## 2. 已确认需求与方案边界

### 2.1 用户明确提出的需求

1. 保留 fork 后修改的功能。
2. 精灵球主工具条仅保留：一键签到、续牌、扩展功能、在线弹幕。
3. 扩展功能保留自动最高弹幕色等五个选项，以及钓鱼。
4. 保留其他与观看直播相关的功能，去掉需要外部支持的功能。
5. 去掉弹幕框“关闭前缀”“拉高”等操作的二次确认。

### 2.2 已通过补充沟通明确的含义

| 项目 | 已确认含义 |
|---|---|
| 五个选项 | 自动最高弹幕色、自动网页全屏、自动最高画质、防页签冻结、阻止 P2P 上传。 |
| 在线弹幕 | 保留现有 `Monitor` 的在线弹幕助手外站入口，作为外部服务唯一的业务例外。不是循环弹幕发送，也不是本地“直播间工具”面板。 |
| 精灵球层级 | 播放器底部观看快捷菜单继续存在；从其中“DouyuEx 工具条”打开的主工具条，与礼物栏精灵球打开的是同一层。这一层只保留四项，不影响播放器的滤镜、画中画和音频等快捷功能。 |
| 循环与定点触发 | 用户要求重新核对这类功能，禁止精简影响正常使用。观时、等级奖励保留后台循环；观看满 30 分钟及之后解锁的奖励仍须自动检查领取，不能仅靠进房或手动签到。 |

### 2.3 已实施的范围

以下取舍已随整份方案确认并实施，具体验证结果见《Lite开发与测试报告》：

- 直播相关能力包含本地弹幕阅读/输入增强、斗鱼同屏与音频、直播回放的时间显示和下载配套；回放功能已保留。
- 账号管理、消费/VIP、背包资产展示、主播道具查询、自动管理直播间等非观看能力已移除。
- 保留签到的现有有效子任务，不按文件名误删它们；等级领奖保持进房立即检查 + 每 35 秒检查，观时领奖保持进房立即检查 + 每 5 分钟检查，与手动签到独立运行。
- 斗鱼以外的平台取流和任意外部地址播放已移除，保留斗鱼同屏；第三方人数数据、查弹幕、外部音效、文案、统计及原作者更新服务已移除。
- 必需的通用前端库继续使用现有加载方式，仅移除不用的库。本方案不包含“全部依赖本地打包、彻底取消 CDN”的额外改造。

这些取舍在后续清单展开；本轮实现以用户已确认的 v0.2 为准。

## 3. 最终入口和交互

### 3.1 主工具条：恰好四项

显示顺序统一为：

```text
一键签到 → 一键续牌 → 扩展功能 → 在线弹幕助手
```

入口关系：

```text
礼物栏精灵球 ──────────────────┐
                              ├─ 主工具条：上述四项
播放器精灵球 → DouyuEx 工具条 ──┘

播放器精灵球 → 滤镜 / 直播流 / 音频 / 增强画中画 / 斗鱼同屏
```

- 关闭按钮属于容器控制，不算第五项业务功能。
- 删除主工具条中其他功能图标，包括更新、小窗、循环弹幕、直播间工具、抽奖、外部推广等。
- 播放器的观看快捷菜单保留，去掉 Joysound 音效项；将原主工具条的“同屏播放”迁入播放器菜单并限定为斗鱼。
- 隐藏礼物栏后，仍可从播放器的“DouyuEx 工具条”打开四项功能，沿用浮动定位。
- 不出现空白占位图标、指向已删除面板的菜单项、重复工具条或不可点击的残留区域。

### 3.2 四项功能的操作

| 功能 | 确定的产品行为 |
|---|---|
| 一键签到 | 单击处理已开播的关注房间，长按处理全部关注房间；其余签到子任务按第 6 节执行，显示各自结果。 |
| 一键续牌 | 保留数量输入、上次输入记忆和输入 0 平均分配；确认数量后赠送荧光棒，取消不发送。 |
| 扩展功能 | 打开五个偏好开关和钓鱼区，不再包含宝箱、红包、礼物批量赠送及视觉身份模拟。 |
| 在线弹幕助手 | 用户点击时打开现有 `https://www.douyuex.com/{当前房间号}`；不在进入直播间时预加载、不引入嵌入页面或自动请求。外站可用性由该服务决定。 |

### 3.3 扩展功能：五个偏好 + 钓鱼区

| 保留项 | 功能 | 设置行为 |
|---|---|---|
| 自动最高弹幕色 | 进入直播间自动选择已解锁的最高档粉丝弹幕色 | 保留 fork 的色板异步等待、普通/比赛房间适配、偏好恢复及定时器变量管理。 |
| 自动网页全屏 | 进入房间自动切换网页全屏 | 沿用原偏好，不改成浏览器全屏。 |
| 自动最高画质 | 自动选择当前可用的最高画质 | 沿用原偏好，不承诺解锁账号不可用画质。 |
| 防页签冻结 | 尝试保持切出标签或画中画时的播放 | 保留与增强画中画的联动，以及已有基础防暂停逻辑。 |
| 阻止 P2P 上传 | 阻止播放器的 P2P 上传路径 | 保留原生效时机；需要刷新时使用非阻塞文字提示。 |
| 自动钓鱼（独立区域） | 开关、全天/比赛时段选择，自动抛竿收竿和结果提示 | 保留按房间保存、恢复设置和鱼饵不足停止等行为。这里的钓鱼开关不计入上面的五个通用偏好。 |

五个通用偏好首次默认关闭，继续读取各自原有设置。钓鱼首次默认关闭，已保存的开启状态按原逻辑恢复。简洁模式的状态单独保存，不能因精简扩展面板而被重置。

扩展功能明确移除：半自动抢宝箱、自动抢礼物红包、按 ID 赠送背包道具、批量常规礼物赠送、清空背包入口、幻神模式、荧光棒变超火、已停用的独立弹幕字号选项。续牌所需的背包查询和赠送能力作为内部依赖保留。

## 6. 签到、续牌与任务的具体范围

### 6.1 一键签到

保留现有已接入且使用斗鱼自身接口的任务，避免把“保留签到”开发成只剩房间签到。界面仍为一个签到入口，不新增任务管理中心。

| 子任务 | 方案处理 |
|---|---|
| 关注房间签到 | 保留单击/长按范围差异。 |
| 鱼吧签到及补签、客户端签到 | 保留原有动作与结果提示；补签仍可能使用补签卡。 |
| 粉丝家园、钻粉联赛签到 | 保留；改为由公共数据层获取粉丝牌列表，不依赖抽奖模块初始化。 |
| 阅读、关注、星推、活动签到 | 保留现有有效调用，包括固定帖子、固定房间及真实关注/取关行为。本轮不将它们误标为第三方服务。 |
| 等级任务已完成奖励领取 | 保留进房立即检查 + 每 35 秒检查；按服务端完成且未领奖状态领取，任务之后才完成也能处理，不改为签到触发。 |
| OPFOY 签到及观时奖励 | 保留按钮内签到；观时奖励独立保持进房立即检查 + 每 5 分钟检查，持续发现之后解锁的任务，按服务端返回状态逐项领取。 |
| 空配置活动执行器、已注释的电视/车队/点赞/广告签到 | 清理未启用入口与无用实现，不恢复历史活动。 |

保留行为的具体含义需要在交付说明中可见：固定房间关注后取关、星推关注任务、固定帖子阅读及鱼吧补签仍属于签到集合。本轮已按用户确认保留这些签到子任务，后续调整需另行变更需求。

接口返回活动结束、未登录或无资格时，提示对应结果并继续其他独立任务，不宣称已完成。避免快速重复点击叠加同一批任务；单个任务失败不得阻断观看界面。

观时循环和等级循环也不得因一次失败被永久停用。领取判断以每次最新服务端状态为准：当前实现分别检查 `task.status === 2`，以及 `taskStatus == 1 && prizeStatus == 0`。不把“签到点过一次”“本轮暂无可领项”或“已领过一个阶段”当成整天任务结束。

### 6.2 一键续牌

- 保留当前荧光棒类型识别、背包数量查询、按粉丝牌房间赠送、输入 0 平均分配、结果提示。
- 保留已有数量输入确认；这里涉及道具赠送，不适用“去掉布局二次确认”。
- 抽离背包查询函数，不能因删除扩展送礼模块而断掉续牌依赖。
- 未登录、无荧光棒、无粉丝牌、数量无效或接口失败时应明确结束/提示，不发起错误赠送。
- 如核验发现既有实现阻止正常续牌运行，应修复保留流程所必需的问题；不扩展新的赠送模式。

### 6.3 循环、时段和到点行为复核

以下频率与触发条件来自当前源码，除最终确认删除的功能外，本轮精简不调整它们的产品语义。某项功能正常收尾时清理对应任务，不等于提前取消仍在使用的调度。

| 编号 | 功能/任务 | 当前触发与时序 | Lite 要求 |
|---|---|---|---|
| T01 | 观时奖励 | 初始化立即查，之后每 5 分钟查 `taskList`；仅对服务端标记可领取的项调用领取 | 完整保留。没有硬编码 30 分钟门槛，用户提到的 30 分钟及其他阶段应由服务端任务状态覆盖；不改成仅签到一次或仅 30 分钟一个闹钟。 |
| T02 | 等级任务奖励 | 初始化立即查，之后每 35 秒重新查询任务 ID、任务完成和领奖状态 | 完整保留。签到、观看等操作完成后新出现的可领取项也能被发现。 |
| T03 | 自动钓鱼 | 启用后先读取当前状态，处理已完成未收竿；每 1.5 秒检查，按服务端 `fishEtMs` 到点收竿并继续下一轮 | 保留完整循环、未收竿恢复和关闭/鱼饵不足停止行为，不改为进入房间只抛一次竿。 |
| T04 | 钓鱼比赛时段 | 当前实现每轮检查本机时钟：12–23 时每小时的第 00–29 分钟，以及 00:00–00:29；非比赛时段跳过动作，循环仍等待下一有效时段 | 保留当前条件和跨时段自动继续；不因暂时不在比赛时间就永久清除循环。此处描述现有代码，不声称线上赛程已经验证。 |
| T05 | 自动最高弹幕色 | 启用/恢复偏好后每 500ms 等待色板，先打开再等渲染，成功或约 50 秒超时后结束 | 保留有限重试和成功后的清理；不能退化为 DOM 未出现时查一次就结束。 |
| T06 | 自动网页全屏/最高画质 | 读取已保存偏好后，每 1 秒等待相关控件，约 100 次上限，找到后应用并停止 | 保留加载等待；模块或页面入口调整不能跳过早期偏好应用。 |
| T07 | 弹幕连接 | 连接后登录/加入房间，每 40 秒心跳；断线后按退避延迟重连，初始 3 秒、最高 60 秒，连续失败有上限 | 保留观看用消息订阅和重连；不能只保留首次连上时的消息。 |

**30 分钟领取场景的正确含义：** 客户端不自行保证“从当前页打开计时满 30 分钟就可领”。已有观看进度、活动起始时间和各阶段资格都以服务端返回为准。测试应模拟进入时尚不可领、观看达到用户提到的阶段后变为可领、之后还有其他阶段，而不是写死只测第 30 分钟一次。当前静态阅读不能确认该 30 分钟任务具体对应哪条线上奖励配置，因此观时和等级两条原有检查链都必须保留。

正常可运行且请求完成的条件下，T01/T02 在下一次原定轮询处理新状态。浏览器后台限频、睡眠或网络失败可能延迟执行，不能承诺在精确墙钟时刻到账；验收重点是恢复运行后后续周期仍会读取最新状态、补处理仍可领取项，不需要用户再点签到或重开功能。

### 6.4 允许清理计时器的条件

- 只有本方案最终确认移除的抽奖列表、红包/宝箱、循环发言、自动管理等功能，其专属轮询、倒计时或事件回调才随之移除。
- 同一旧模块含保留和删除能力时，先按实际调用拆分；例如删除 Lottery 不删除粉丝牌加载，删除 LiveTool 面板不删除观看消息订阅，删除第三方统计不删除官方时长刷新。
- 不能仅按 `setInterval`、`setTimeout`、`sleep`、动画帧或所在目录批量删除；必须检查触发入口、执行目标、复用方和停止条件。
- 单个页面/功能实例不能在重复初始化后叠加同一轮询；异步请求慢于周期时避免重叠领取，且不得以防重入为由把未来轮次永久锁死。
- 去重判断不能跨活动周期、日期或账号错误复用旧结果；使用最新服务端任务状态和周期信息，不把“曾成功过”当成永久不再检查。

1. 固定功能白名单及入口顺序，先抽离粉丝牌、背包和观看消息依赖。
2. 收拢主工具条与扩展面板，迁移斗鱼同屏入口，整理播放器菜单。
3. 拆分混合模块，移除外部服务、管理功能及无关数据功能。
4. 整理手动签到与自动领奖的独立入口，保留第 6.3 节时序，确保续牌依赖完整。
5. 修复前缀/拉高确认及保存恢复一致性。
6. 清理死代码、库、权限、路由和脚本说明，构建产物。

| A27 | 小窗/延迟加载/信息刷新 | 主页面切到后台后，画中画已有保活/恢复仍可用；控件迟到仍能应用选色、画质等偏好；关注列表、屏蔽/收藏面板再次打开或重渲染后，原有观察与挂接仍有效，画中画控制栏同步和夜间模式适配继续生效；官方时长多轮刷新。关闭小窗后对应任务正确清理。 |
| A28 | 批处理与跨月活动 | 替身请求验证鱼吧失败重试/补签、阅读 5 次、星推 500ms 间隔和续牌 250ms 间隔；跨月重新获取活动配置，并覆盖当前月无配置时前月/后月回退。 |
| A29 | 后续事件与连续渲染 | 页面打开后才出现的开播消息、榜单变化、动态面板仍可处理；截图/GIF 区分正确且 GIF 包含连续帧，全景持续更新；用户暂停与小窗退出不被后台恢复逻辑覆盖。 |

以构建/静态引用检查、针对隐藏依赖与状态切换的必要测试，以及页面交互回归验证。涉及真实送礼、关注/取关或钓鱼消耗的验收先用替身请求验证调用，真实账号动作需单独明确测试范围；不能把 mock 成功表述为线上操作成功。

A21–A29 使用可控时钟、服务端状态替身及模拟事件覆盖多个周期和边界，避免仅用“页面打开没有报错”证明时序正确；保留长时页面回归作为补充。要求是可观察功能和领取机会不因精简而退化，不声称仅凭静态检查已验证线上奖励。
